> 审查范围：`tab/server`（相册接口 + COS 集成 + 图片处理）、`tab/client`（相册前台）、`tab-desktop`（相册管理）
> 审查日期：2026-10-18

## 一、结论速览

| 维度 | 现状 | 评级 |
|---|---|---|
| 密钥存储 | SecretId/SecretKey 经 AES-256-GCM 加密入库，读接口不回传明文 | ✅ 合格 |
| 密钥权限 | 使用的是**主账号密钥**，拥有整个账号的 COS 全权限 | ❌ 高风险 |
| 上传校验 | 实际解码校验（非只看 Content-Type）+ 1 亿像素上限 + 15MB 上限 | ✅ 本次已加 |
| 上传限流 | 全局 300 次/分 + 上传 120 次/分 | ✅ 本次已加 |
| 图片缓存 | `max-age=31536000, immutable` + 随机文件名 + ETag 304 | ✅ 合格 |
| 图片体积 | 新图转 WebP；**存量老图为 PNG，单张 1.47MB** | ⚠️ 待迁移 |
| 防盗链 | **未配置**，URL 可被任意站点直接引用 | ❌ 最大盗刷风险 |
| 用量封顶 | **未配置**，被盗刷时无止损线 | ❌ 高风险 |
| 存储桶权限 | 目前支持公网直读（源站域名直连） | ⚠️ 建议改私有读 + CDN |
| 流量成本 | 未开 CDN，全部走 COS 外网下行 | ⚠️ 贵约 2.5 倍 |

**一句话结论**：代码侧的密钥加密、缓存、上传校验已经达到及格线以上；真正的风险全部集中在**腾讯云控制台侧的 4 项配置没做**——防盗链、用量封顶、子账号密钥、CDN。这四项做完，盗刷风险能降一个数量级。

## 二、本次已落地的代码加固

| # | 改动 | 解决的问题 |
|---|---|---|
| 1 | 图片统一转 **WebP**（quality 82） | 同画质比 JPEG 小 25%~35%，比 PNG 小 60%~80% |

| 6 | 相册名白名单清洗（只留文字/数字/空格/-_·()） | 排除 `/ \ : ? # %` 等破坏 URL 与路径的字符 |

## 三、P0：必须做（都在腾讯云控制台，约 30 分钟）

### 1. 换成子账号密钥，只授权这一个桶
路径：访问管理 CAM → 用户 → 新建子用户（编程访问）→ 只附加自定义策略：

```json
{
  "version": "2.0",
  "statement": [{
    "effect": "allow",
    "action": ["cos:PutObject", "cos:GetObject", "cos:HeadObject", "cos:DeleteObject"],
    "resource": ["qcs::cos:ap-guangzhou:uid/1250000000:my-bucket-1250000000/*"]
  }]
}
```

拿到新密钥后，在桌面程序「设置 → 对象存储」里替换即可（旧密钥在 CAM 里禁用）。
**为什么重要**：现在这把钥匙能操作你账号下**所有** COS 资源，一旦泄露（日志、截图、聊天记录）损失不可控。

### 2. 配置防盗链（Referer 白名单）— 这是防盗刷最关键的一步
COS 控制台 → 存储桶 → 安全设置 → 防盗链：
- 开启防盗链，类型选**白名单**
- 允许：`*.example.com`、`localhost`、`127.0.0.1`（本地开发）
- 允许空 Referer：建议**否**（除非你有 App/小程序直连需求）

这样别人把你的图片贴到自己网站上，访客看到的是一张 403 提示图，而不是消耗你的流量。

### 3. 打开用量封顶（止损线）
两处都要设：
- **CDN 控制台 → 用量封顶**：日流量上限（例如 5GB/日），超额自动停用
- **COS 控制台 → 存储桶 → 用量封顶**：外网下行流量日上限

**为什么重要**：这是被盗刷时唯一能自动止血的机制。没有它，一晚上能跑掉几千块。

### 4. 关闭存储桶的「公有读」以外的多余权限
- 存储桶列表 → 权限管理 → 访问权限：**私有读写**（如果走 CDN 回源）或**公有读私有写**（如果不走 CDN）
- 关掉「公有读 + 列举」组合，否则别人可以遍历你整个桶的文件清单

> 如果改私有读，必须配 CDN 回源访问权限，否则前台图片 403。建议顺序：先配 CDN → 验证 → 再改私有读。

## 四、P1：流量与成本优化（建议做，收益明显）

### 1. 双尺寸图片（省 60%+ 流量，最大的一笔）
现状：瀑布流里 3 列图片，每张却加载 1600px 大图。
方案：上传时同时生成 `800px 缩略图` 和 `1600px 大图`，列表用缩略图，点开灯箱才加载大图。
- 需要给 `Photo` 加 `thumb/thumbKey` 字段（一次数据库迁移）
- 预计单张从 ~250KB 降到 ~60KB，首屏 20 张图从 5MB 降到 1.2MB

### 2. 开启 CDN 加速
COS 外网下行约 0.5 元/GB，CDN 约 0.2 元/GB，且边缘命中后不回源。
你的 `cdn.example.com` 已经绑好，只差：DNS 加 CNAME + 配 HTTPS 证书（详见之前的说明）。
做完后**代码与配置一个字都不用改**（第 8 条改动就是为此准备的）。

### 3. 存量老图迁移（PNG → WebP）
现有「洛阳」相册 3 张照片是 1600px PNG，单张 1.47MB。
可跑一次性脚本：下载 → 转 WebP → 上传新 key → 更新数据库（原文件保留不删）。
预计：1.47MB → 200KB 左右，省 85%。

### 4. 图片处理服务（可选，替代方案）
存储桶开启「数据万象」后，可直接用 URL 参数动态出图：
`?imageMogr2/thumbnail/800x>/format/webp/quality/80`
优点：不用改数据库、不用存两份；缺点：按处理次数计费，且只对开启该服务的桶有效。

### 5. 相册列表分页
现在 `/api/albums` 一次返回全部（当前 21 个）。到几百个时 JSON 会变大。
建议加 `?page=1&pageSize=50`，前台按需加载。

## 五、P2：加固与运维

| 项 | 建议 |
|---|---|
| CORS 收紧 | `.env` 里 `CORS_ORIGIN=*` 改为 `https://你的域名` |
| 加密主密钥 | 生产环境改用环境变量 `COS_ENC_KEY`（32 字节 hex），别依赖 `data/.cos-secret` 文件（Windows 上无法设 600 权限，实测是 644） |
| 操作审计 | 相册增删改记录一条 `AuditLog`（谁、什么时候、改了什么），异常时能追溯 |
| 孤儿文件清理 | 删除相册保留 COS 文件是你的需求，但长期会积累。建议做一个「扫描 COS 中存在、数据库中无引用」的清理脚本，**先 dry-run 出清单**再人工确认 |
| 监控告警 | 腾讯云「云监控」对 COS 外网流量、请求数设阈值告警（如日流量 > 2GB 告警） |
| 备份 | 相册图片建议开存储桶「版本控制」或跨地域复制（可选） |
| 上传来源校验 | 上传接口已需登录 + 限流；如需更严，可加「仅允许内网/办公 IP 调用管理接口」 |
